# Testing And Acceptance Plan

This checklist covers both the backend API extension and the future KMP app.

## Backend Verification

Run these commands before claiming the backend work is ready:

```bash
./gradlew spotlessCheck
./gradlew test
./gradlew build
```

Docker must be running for Testcontainers. If Docker is unavailable, run focused non-container checks and state that the
full suite was not executed.

## Backend Test Cases

### Auth And Passkey Signup

Add tests to `AuthRouterTest` or a new passkey-focused test class.

- `POST /api/auth/passkeys/signup/options` returns `200 OK` and WebAuthn creation JSON for a new valid email.
- Signup options reject invalid email with `400 Bad Request`.
- Signup options reject an existing email with `409 Conflict`.
- Signup finish rejects malformed credential JSON with `400 Bad Request`.
- Signup finish rejects an expired, consumed, or replayed challenge with `401 Unauthorized`.
- Signup finish creates a user with `password_hash = null`, creates the credential, and returns `TokenResponse`.
- Password login still succeeds for existing password users.
- Password login returns `401 Unauthorized` for passkey-only users.
- Existing authenticated passkey registration routes still require JWT auth.
- Refresh token rotation and logout behavior remain unchanged.

### Feed Behavior

Add or update tests in `FeedRouterTest`.

- Empty `GET /api/feeds` returns `200 OK` with `[]`.
- Non-empty `GET /api/feeds` still returns only the authenticated user's feeds.
- `DELETE /api/feeds/{nanoId}` deletes the authenticated user's feed and returns `204 No Content`.
- Deleting another user's feed returns `404 Not Found`.
- `POST /api/feeds/{nanoId}/sync` returns a summary and updates `synchronizedAt`.
- Syncing another user's feed returns `404 Not Found`.

### RSS Sync And SSRF

Use a local HTTP test server rather than live podcast URLs.

- Sync creates episodes from a valid RSS feed with audio enclosures.
- Sync updates an existing episode when the same `(feed_id, guid)` appears with changed metadata.
- Sync skips items without playable audio enclosures.
- Sync handles Atom feeds if the chosen parser supports them.
- Sync rejects malformed XML with `400 Bad Request`.
- Sync rejects unsupported URL schemes such as `file:`, `ftp:`, and `jar:`.
- Sync rejects `localhost`, `127.0.0.1`, `::1`, RFC1918 private ranges, link-local, multicast, and wildcard addresses.
- Sync rejects redirects to private or unsupported URLs.
- Sync stops after the configured redirect limit.
- Sync rejects a response body over the configured maximum size.
- Sync times out cleanly on slow connect or read.

### Episodes And Progress

Add tests under `src/test/kotlin/io/pcast/module/episode/api/`.

- `GET /api/episodes` requires authentication.
- `GET /api/episodes` returns only episodes from feeds owned by the authenticated user.
- `GET /api/episodes?feedId=<nanoId>` filters to the requested feed.
- `GET /api/episodes?limit=0` returns `400 Bad Request`.
- `GET /api/episodes?limit=101` returns `400 Bad Request`.
- `GET /api/episodes?before=<iso>` returns older episodes sorted newest first.
- `GET /api/episodes/{id}` returns one owned episode with progress when it exists.
- `GET /api/episodes/{id}` returns `404 Not Found` for another user's episode.
- `PUT /api/episodes/{id}/progress` upserts progress and returns `204 No Content`.
- Progress update rejects negative position with `400 Bad Request`.
- Progress update rejects duration less than position beyond the 5-second drift allowance.
- Progress update rejects another user's episode with `404 Not Found`.
- Updating progress twice overwrites the previous row for the same `(user_id, episode_id)`.

## KMP Unit Tests

### Serialization

- `TokenResponse` decodes backend JSON with `tokenType = "Bearer"`.
- `FeedResponse` decodes nullable `synchronizedAt`.
- `EpisodeResponse` decodes nullable description, duration, image URL, and progress.
- Unknown backend fields do not fail decoding.

### API Client

- Adds `Authorization: Bearer <accessToken>` to authenticated calls.
- Does not attach bearer tokens to signup/sign-in options calls.
- Refreshes token on first `401`, retries the original request once, and stores the new token pair.
- Does not retry indefinitely after refresh failure.
- Converts backend `{ "message": "..." }` errors into user-facing error state.
- Clears session and cache on logout.

### Repositories And Cache

- Feed list replaces local feed cache.
- Episode list upserts local episode cache.
- Feed deletion removes cached feed and cascade-removes cached episodes.
- Progress update writes local optimistic state and enqueues/pushes server sync.
- Newer server progress wins over older local progress.
- Local unsynced progress is sent before a stale server value can overwrite it.

### View Models

- Auth view model handles signup options, platform credential creation, finish, and signed-in transition.
- Auth view model handles sign-in options, platform assertion, finish, and signed-in transition.
- Subscriptions view model loads feeds, adds a feed, deletes a feed, and triggers sync.
- Episode list view model loads all episodes and feed-filtered episodes.
- Player view model loads an episode, resumes from progress, saves every 15 seconds, saves on pause, and marks completed.

Use fake implementations of `ApiClient`, `TokenStore`, `PasskeyAuthenticator`, and `AudioPlayer` for common tests.

## End-To-End Acceptance Scenario

The MVP is accepted when this scenario succeeds against a fresh database:

1. Start the API with PostgreSQL.
2. Start the Android app.
3. Sign up with email and passkey.
4. Add one public podcast feed URL.
5. Sync the feed and see at least one playable episode.
6. Play an episode for at least 30 seconds.
7. Pause playback and confirm progress is saved.
8. Start the iOS app, sign in with the same passkey account, and open the same episode.
9. Confirm playback resumes near the Android pause position.
10. Pause from iOS and confirm progress is saved.
11. Start the Desktop app, sign in through the browser WebAuthn bridge, and open the same episode.
12. Confirm playback resumes near the iOS pause position.
13. Sign out on each target.

## Release Readiness Checklist

- Backend route documentation is updated in `README.md`.
- Bruno collection includes all new backend routes.
- Backend migrations run against an empty local database.
- Backend migrations run against a database containing password users.
- Existing password users can still log in.
- Passkey-only users can sign up and sign in.
- Episode sync rejects SSRF attempts.
- App README documents Android, iOS, and Desktop run commands.
- App stores tokens securely on every target.
- App does not store raw tokens in SQLDelight.
- App handles offline API errors without losing local progress.
- App progress sync is verified across Android, iOS, and Desktop.
